# Clean setup (P1): live plan, 2026-11-10

This is the plan the live evaluation protocol asks for before any call (`ENG-07`, [live evaluation](../../docs/practices/live-evaluation.md)). It covers M3's exit criterion "the setup check guides a fresh machine to a working connection, with Claude Code and with Codex: the clean-setup scenario (P1) passes once in Windows Sandbox" ([M3 roadmap](../../docs/roadmap/m3-verification-and-codex.md)). **Nothing that calls a model runs until the owner approves the limit below.** The steps are in the [procedure](../../docs/testing/clean-setup.md).

# What runs

The owner follows the procedure in Windows Sandbox, at `origin/main`. The setup check runs from Claude Code missing, through not signed in, to ready; then the same for Codex. The setup check itself spends no model call (L-71). The model is called only by T1's opening request, asked once with each program, each in a new workspace: "I need a shopping list I can tick off at the store. We need milk, eggs, bread and apples."

- **No harness counts these calls.** They come from a real Tessera in the sandbox, signed in to the owner's accounts. The limit is how Tessera bounds a request: each new tool gets one repair of each kind of failure (its data's shape, the static check, the smoke check and the behavior check, `GEN-09`), so one request makes at most 6 calls.
- **Two requests, never repeated.** A request that fails is recorded as failed, and no other request is asked.
- **The status screen's probe isn't used.** It would cost a call each time.
- **M3's envelope** is about 65 calls, with 56 used ([budgets](../../docs/roadmap/budgets.md)). The expected 4 leave about 5. The worst case of 12 would pass the envelope by 3, which the owner accepts by approving this plan, or declines by asking for Claude Code only (expected 2, at most 6).

# Expected tokens and time

From the M3 live run's T1: intent about 5,000 input and 500 output tokens; create about 10,000 input and 3,000–8,000 output. The two requests together are about 30,000 input and 15,000 output tokens, and a few minutes of model time. Preparing the sandbox takes a few minutes, and the whole run about 30 to 45 minutes, in one sitting.

# Stop rules

- **The sandbox can't be prepared** (a download or the install fails): the run stops before any call, and the failure is fixed first.
- **The setup check can't be followed** for a program, so it never reaches ready: that program's request isn't asked, and the gap is the result.
- **A provider error** (sign-in, unavailable model, usage limit): that program's request ends, and it isn't asked again.

# What to watch

The check's fix for a missing program today says only "Install it, then try again", which may not meet `PLAT-03`'s "the exact fix". If the owner has to look anything up, it is a finding, not a deviation.

# Record

- **The procedure's record:** each screen's words, screenshots, each request's outcome, calls and time, and the owner's verdict on each tool.
- **A results report** in `evals/reports/`, with the exit criterion's result and a lessons entry and fix for every defect (`ENG-13`).
- **Nothing private:** the sandbox and its sign-ins are discarded on close, and screenshots are checked before they are kept (`ENG-19`).

**Asking for:** approval of two requests, 4 calls expected and at most 12, with both programs, in M3's envelope.
