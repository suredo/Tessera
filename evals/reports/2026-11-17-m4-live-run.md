# What failed, and why

## T3: a diagnostic that read as a forbidden name

The chart's creation wrote its data schema as a map of lists, `{ "entries": { "type": "array", … } }`, without `type` and `properties`. The host said `uses "entries", which a tool's data schema can't use`, which reads as a forbidden name, so the repair renamed the list to `expenses` and was refused the same way. **L-103**, fixed in [#394](https://github.com/suredo/Tessera/pull/394): such a key is now told it belongs under `properties`, with the shape, and the creation prompt shows the shape.

## T10 in Portuguese: flashcards added to the planner

"Faz cartões de memorização destas anotações…" was read as a change to the planner plus two cards (`mixed`, cards), where the English run made a second tool, as the scenario expects. Three things followed:
- **The cards weren't saved.** No declarative migration adds a list; the change's required `cards` failed to migrate, its repair made the list optional, and adding the two cards to a list the data didn't hold was refused. **L-104**, fixed in #394: a list a changed shape adds starts empty.
- **The cards part has no check.** A change keeps its tool's profile (L-94), so the version is the planner's, and its cards have neither the cards hooks nor the cards check. Whether a tool may grow a second kind of part, and how it is then checked, is the owner's to decide.
- **The scenario's expectation:** both readings are fair; the scenario names one.

## T12: a board without its filter

The intent named item-list, so the board had no `item-category` or `filter`: two do steps failed, and Dishes was saved as Ana's, the first person in the board's list. The requests themselves passed.

## T14: two buttons marked as the edit

The editor marked crop, rotate, black-and-white and others all `image-edit`; the profile's hook says "a button that makes one edit", which doesn't say only one, so the step couldn't choose. The profile's wording, or the step, needs to say which.
