# T10: the static repair that didn't hold

T10's first request made a study planner with 10,579 output tokens:
- **The created tool:** the static check (`VER-01`) refused it: "The JavaScript uses Object.entries on an element or the page. Name the properties you need." The tool used `Object.entries` on its own saved records, which the check can't tell apart from an element or the page.
- **The one static repair** (`GEN-09`): it replaced `Object.entries` with `for…in` and `o[id]`. The same rule refuses those: listing properties with `for…in`, and a property reached by a name computed at run time. Because of `o[id]`, a data write on line 99 also counted as a startup write.
- **The result:** the person saw "That didn't work. The tool Tessera made didn't pass its checks, so nothing was changed." ([screenshot](2026-11-09-m3-live-run/T10-step-1.png)). The step failed, the rest were blocked, and 3 of T10's 12 calls were used.

The check is right to refuse code it can't prove safe, so it stays as it is. The gap is in what the finding tells the model: "Name the properties you need" doesn't fit records kept by ID. The finding (or the prompt) needs to give a form the check accepts, such as records in an array found by their `id`. M2's T6 needed the same kind of static repair and got through, so this looks like a recurring class rather than one unlucky answer.
