# Scoring, frozen before the run

- **Requests at the first attempt** (A40): 12 model-dependent steps, the denominator above, fixed now. A step blocked by an earlier failure still counts against it. The target is 85%, which means at least 11 of 12. Automatic repairs are counted separately, and don't make a step fail.
- **Lifecycle steps:** 11, and every one must pass.
- **Every step:** the host facts (`EVAL-02`): nothing unrelated changed, no saved tool's Continue moved, and no success claimed that wasn't applied (`GEN-08`).
- **The run passes M2's exit criteria for the live run** when there is no false success message and no data loss (the roadmap's words). Finding a saved tool by asking must work in T1's step 8 (`GEN-18`, the open part of [issue 145](https://github.com/suredo/Tessera/issues/145)).
- **The first-attempt rate, stage times and speed figures** are recorded for the time-limit update (`OBS-04`, issue 154).

# Stop rules

- **The first step of a scenario fails:** that scenario stops. Its other steps are blocked and counted.
- **A step fails:** it isn't retried (there are no retries). The scenario continues, because each step is judged on its own. A second failure of the same kind across scenarios stops the run, to fix the cause offline before spending more.
- **A provider error** (sign-in, unavailable model, unsupported effort): the harness refuses every later call, and the run stops.
- **A usage limit:** pause. The remaining scenarios resume after it resets, and finished ones aren't run again.

# Before the run: the live mode (no calls)

The runner has only rehearsal and replay modes today. One small PR, reviewed before anything is spent:

- **Live mode:** the CLI's `--live --cap <n>` uses the Claude Code provider with the approved cap `n`. It refuses to start without a cap, with a cap above the scenario file's budget, or without the setup check passing. So option B's 9-call cap for T1 runs as approved, and nothing can raise a cap past its file.
- **Recording:** after a live run, each call's parsed answer is written as an answers file under `evals/scenarios/replays/`, with saved tools named as `{{saved:<name>}}`, the prompt parts recorded and the run's head. Replays then run offline (`EVAL-07`, `TEST-04`).
- **Each scenario's video, screenshots, ledger and report** are kept under `test-output/evals/scenarios/`. A sanitized copy of the report and the chosen screenshots is committed here.
