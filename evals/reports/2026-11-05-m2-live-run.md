# Stop rules

- **The first step of a scenario fails:** that scenario stops. Its other steps are blocked and counted.
- **A step fails:** it isn't retried (there are no retries). The scenario continues, because each step is judged on its own. A second failure of the same kind across scenarios stops the run, to fix the cause offline before spending more.
- **A provider error** (sign-in, unavailable model, unsupported effort): the harness refuses every later call, and the run stops.
- **A usage limit:** pause. The remaining scenarios resume after it resets, and finished ones aren't run again.

## Defects found

Each gets a lessons entry, a replay test and a fix (`ENG-07`, `ENG-13`), in later pull requests:

1. **Continue leaves the earlier message on screen** (above). Found by looking at the screenshot; the host facts don't read messages.
2. **When an edit changes nothing, the model's explanation is dropped:** the person reads "The tool wasn't changed." without the reason (that the board already has an eraser, `GEN-08`, `GEN-12`).
3. **A cancel says "That didn't work. The request was stopped."** Nothing failed: the person asked to stop (`GEN-12`).
4. **The tool panel is blank in the screenshots after a data change from chat, Use again and Continue.** It shows in the free replay and in the morning's rehearsal too, so it isn't the model's; it looks like [L-76](../../docs/lessons/tessera-issues.md)'s frame-capture limitation, to be confirmed by waiting for the tool's rows before the screenshot. Confirmed on 2026-11-06 as timing, not the model or L-76: the screenshot was taken before the newly opened workspace's tool had loaded, and the runner now waits for it (L-81).
