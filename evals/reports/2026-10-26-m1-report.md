## What M1 learned

- **Review found real defects, often.** Codex's reviews found at least one real problem in most pull requests of the host app: a stale "last used" date, a race between two restores, a history that missed the tool's own changes, a download name that broke on rare characters, and a development folder check that a link could fool. Each was fixed with a test that failed first.
- **Tests that wait on time were the main source of flakiness.** M1 opened eight issues for intermittent failures (#65, #79, #81, #83, #94, #98, #103, #106), and three more were fixed straight away in pull requests: two unit-suite timeouts (#125, #131) and the keyboard accessibility test's (#134). All were timing under load; none was a product bug. Each was measured first. The fixes set one unit-test limit with its reason (#131), and made the browser tests wait for a page's script on a timer rather than on animation frames (#129).
- **A tool's frame can't submit a form.** The sandbox allows scripts only, so a `<form>` never submits; the first sample tool silently saved nothing (#127). Generated tools (M2) need the same care.
- **Command chains need gates.** Twice a chain of commands pushed and reported results after a failing test, and once a reply claimed a clean run that wasn't. Each was corrected on the pull request. Pushes now run only after the checks pass.
