## Tracking rules review

Read against every M0 issue and pull request.

- **Milestone and area label (`ENG-28`): followed.** All 15 issues and all 19 merged pull requests carry M0 and one area label. #1–#6 predate the rules (A54). The one exception is #23, a throwaway CI demonstration closed without merging; that's fine for a draft that never lands.
- **Links instead of restating (`ENG-28`): followed.** Issues link their roadmap row and quote only its name; requirement IDs are links.
- **One brief per task (`ENG-29`): followed.** The 15 deliverables became issues when M0 started. Work done in one session kept its brief in the pull request (#21, #41). Partial work said `Part of #N` (#24, #35), the rest `Closes #N`.
- **Where the line between issue and pull-request-only work fell:** the deliverables, which waited or spanned sessions, had issues. Small corrections found along the way had issues when they were left for later (#25, #30) and none when done at once (#21). #41 is the boundary case: proposed here as a follow-up session and done there in one go, its brief in its pull request. That fits the rule as written; if follow-ups started from another session should get issues, `ENG-29` should say so.
- **What M0 adds to the rules:**
  1. **Several pull requests merged after more than one review round** (#37, #38, #39, #40, #41). Each fix got its own commit and a re-review of the new head before merging. This worked and could be written into the cross-review procedure.
  2. **Merging needs green CI on the exact reviewed commit.** Editing a pull request's description restarts CI and cancels the run in progress, and `gh pr checks` then shows the cancelled jobs as failures. Merges were tied to the reviewed commit (`--match-head-commit`).
  3. **Stacked pull requests and squash merges conflict.** After #35 and #40 were squash-merged, their stacked follow-ups (#36, #41) needed `main` merged in. The retarget-first rule in `AGENTS.md` held.
- **Reconciling issues before sign-off (`ENG-30`): no issue is open in M0,** so none moves. The open items below go to their homes.
