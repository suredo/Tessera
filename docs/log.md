## 2026-10-19

* **Creation**: The [launcher](code/server/launcher.md) code doc ([issue 54](https://github.com/suredo/Tessera/issues/54), second part): `Tessera.cmd` starts one copy per data folder through the [local server](code/server/local-server.md), on port 4317 or a free one, opens the browser and stops cleanly when its window closes (`PLAT-02`). CI's Windows job runs its tests, as the [CI workflow](code/ci/workflow.md) doc says, and the [platform helpers](code/server/platform.md) doc names it as a user. The data folder's default stays provisional until `PLAT-04`. After Codex's review of [pull request 61](https://github.com/suredo/Tessera/pull/61) found that two launches recovering a stale lock could both start, the running copy holds an operating-system lock, through [storage](code/server/storage.md)'s new `tryLockFile`, that the system releases when the copy ends, and only the holder writes its address in `tessera.address`; the launcher doc's invariants say so and its pitfall about the race is gone. After Codex's second review, a launch that fails once its server has started, as when writing the address fails, closes that server before releasing the lock.

* **Update**: After Codex's second review of [pull request 59](https://github.com/suredo/Tessera/pull/59), the tripwires in the [threat model](spec/threat-model.md)'s shared test helper check every entry a recursive copy (`cp`) reaches, since Node follows links inside the copy where no patch sees them; a link deep in the copied folder that leads outside is refused.

* **Update**: After Codex's review of [pull request 59](https://github.com/suredo/Tessera/pull/59), the tripwires in the [threat model](spec/threat-model.md)'s shared test helper judge a file by where its path really leads, so a link or junction inside an allowed folder can't reach outside unseen, and they refuse requests on connections opened before arming, such as fetch's pool; the threat model says what they still don't see.

* **Update**: The [threat model](spec/threat-model.md) names the shared test helper for its server-side checks, `packages/server/test/support/tripwires.ts`: while armed, it records and refuses network connections, processes, workers and file access outside the allowed folders, and a canary file shows whether anything outside was changed. IMP-07 and MIG-05 use it; it is a test aid, not an isolation mechanism (`SEC-01`).

* **Creation**: The [local server](code/server/local-server.md) code doc ([issue 54](https://github.com/suredo/Tessera/issues/54), first part): the server binds to 127.0.0.1 only, on port 4317 or a free one, refuses any foreign Host header, takes same-origin API requests only, and serves runtime documents on `localhost` only as frames of the host app or the runtime (`SEC-03`). CI's Windows job runs its tests, as the [CI workflow](code/ci/workflow.md) doc says, and the [platform helpers](code/server/platform.md) doc names its new user. After Codex's review of [pull request 60](https://github.com/suredo/Tessera/pull/60), a malformed request target such as `//[` gets 400 instead of stopping the server, and the doc says nothing a request sends stops it.
