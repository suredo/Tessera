| A60 | Refusing tools for writes at startup | **The static check no longer refuses them; the bridge refuses the write when it happens** | Chosen by the owner on 2026-11-10, in hands-on testing, reversing the M2 choice to keep the check strict (L-84). The check guessed from the code which calls run while a tool starts, and refused working tools: two of M2's, and a kanban's drag and drop, whose `classList.add` it took for the tool's own `add` (L-95). The person's data is kept safe without it, by what was already there: the bridge refuses any write before the person's real interaction and throughout staging (`GEN-06`), and a behavior check's writes go to a throwaway copy (`BRG-06`). A data change can be undone from the history (`DATA-04`). A note when an accepted tool changes entries before the person has touched it was offered, then dropped: the bridge's guard already refuses such a change, so the note could never show. |
| A61 | Questions of fact | **A discussion also answers a question of fact from the model's memory, said as such, and "add it" puts the figure in the tool's entries, as any entry change: an addition at once, undoable, and a change to an existing entry after review** | Chosen by the owner on 2026-11-12, in hands-on testing (L-100): asking "what was Brazil's GDP?" beside a GDP chart was read as an entry change, or as unclear, and nothing answered it. The answer says it is from memory, not looked up, with its year; Tessera still can't look things up, and a data source (`CAP-02`, D11) takes over facts that must be current when it lands. The entry stage is told the answer, quoted, as creation and edits are (`GEN-19`). |
| A62 | Context across requests | **Each subject's chat is kept and searchable, and every request is told the last exchange and the earlier turns that share its words** | Chosen by the owner on 2026-11-12, in hands-on testing (L-101): a list was answered as unclear, and "remove what I just listed" had nothing to go on, since each request was read alone. A subject is a workspace, or the empty screen for what is said with no tool open, which now keeps its chat too. Keyword search (SQLite's full-text index, accents and case aside) finds earlier turns within the subject; the last exchange is always told, since "that" and "it" share no words with what they mean. What is told is quoted data, capped within every stage's budget. Embedding-based retrieval may come later, behind the same search. Built in three steps ([#338](https://github.com/suredo/Tessera/issues/338)); amends ADR 0011. |
| A63 | Static style checks for the UI standard | **Notes, never refusals: the standard is the look for whatever the person didn't specify, and what they asked for wins without their having to say they don't want the standard** | Chosen by the owner on 2026-11-13, for [#324](https://github.com/suredo/Tessera/issues/324): a strict check would refuse a blue button the person asked for, or make them ask to leave the standard. So the host only notes where a standard-mode tool's look differs (a shadow, a gradient, a glass effect, fixed or sticky, its own font or colour), in a few words each, at most three and a count of the rest. A change applied as the standard says, by overriding a `--ui-*` variable in `:root`, is never noted; custom mode gets none. The notes are worked out from the code when needed, so nothing is stored. An edit is told them, quoted as data, to keep what the person asked for and bring the standard back elsewhere in what it touches; the details view lists them. |
| A64 | Checks of the person's own policies | **A person's policy, such as "never on Fridays", is their data, not a check: a behavior check tests that rules work, with a rule of its own on a throwaway copy, and never holds a tool to the person's rules; nothing records a policy's version** | Chosen by the owner on 2026-11-13, for [#323](https://github.com/suredo/Tessera/issues/323), amending `VER-05`. In the POC a check carried the policy itself, so it imposed a rule nobody asked for (L-28) and had to be bound to the policy's version. Here a rule is an entry in the tool's data, with its history and undo (`DATA-04`), so "Fridays are allowed now" is an entry change, and no check or evidence depends on it. The scheduling profile's check adds a rule against one of its own sessions' weekdays and removes it again, keeping the rules it started with (`BRG-06`). Evidence belongs to the version it checked (`VER-08`), and a check is chosen by the intent, never by markup; an edit adds no check to a tool made without one (L-94). Building a policy version, as #323's brief described, would have repeated what the data's history already keeps. |
| A65 | Outside data (D11) | **No vetted sources: the person adds connections to any service; a tool uses one by name through the host, reads run freely, its first write through a connection is confirmed, and checks never reach the real service** | Chosen by the owner on 2026-11-14 ([ADR 0015](adr/0015-person-connections.md)), after a comparison of movie sources for T7: Tessera shouldn't limit what a person can reach, whether to fetch from a particular API or to add something through one. Amends `CAP-02` and P7; closes D11. |
